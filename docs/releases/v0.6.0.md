# LeanMark v0.6.0

LeanMark 0.6.0 adds a text width setting and a settings panel that lists the
keyboard shortcuts, and zoom no longer enlarges the toolbar. A reader asked
for the first two in issue #6.

## Release assets

| Platform | Artifact |
| --- | --- |
| Windows x64 | **LeanMark-v0.6.0-windows-x64.zip** |
| Ubuntu 24.04 / Debian-compatible x86-64 | **LeanMark-v0.6.0-linux-x86_64.deb** |
| macOS Intel and Apple silicon | **LeanMark-v0.6.0-macos-universal-preview.zip** |

Every artifact has an adjacent **.sha256** sidecar in this release.

## New

- **Text width.** Narrow (the 720 px column of 0.5.0, the default), Wide
  (960 px) and Full (the window less its margins). Ctrl+Shift+L steps through
  them, and LeanMark remembers the choice. Code blocks, tables, diagrams and
  images stay inside the window at every width.
- **Settings panel.** A settings button in the toolbar, Ctrl+/ or F1 opens a
  panel beside the document to change the theme, text width and zoom. It
  lists every keyboard shortcut, built from the same tables the key handlers
  use. Escape closes it.
- **Theme dot.** The theme button shows a dot with one colour per theme, so
  you can see which theme is on. The tooltip and accessible name also name
  the theme, for example "Theme: Dusk (Ctrl+Shift+T)".

## Fixed

- Zooming enlarged the toolbar and the tab strip too. Each host now keeps its
  web view at 100% and the reader zooms only the document. A zoom level saved
  by 0.5.0 loads at the same text size.
- The "Image unavailable" note was a light cream box in the dark themes. It
  now uses each theme's own colours.

## Settings from 0.5.0

A settings file from 0.5.0 has no width, so it opens in Narrow, the column you
had before. 0.5.0 reading settings written by 0.6.0 ignores the new width value.

## How it was measured

In the `launch-time` workflow on Windows, the document was ready in a median
571.0 ms for simple.md and 713.4 ms for showcase.md, against 572.6 ms and
708.8 ms for v0.4.0, the newest tag that workflow can build. On Linux, memory
5 seconds after opening was 0.6% higher than main for simple.md and
0.2% higher for showcase.md, and start to first check took
a median 452.5 ms against 436.5 ms, with overlapping quartiles. The reader page
is about 5 KB larger after gzip. The Windows, Linux and macOS test suites
pass.

## Installing

On Windows, run the installer from the extracted ZIP:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installer\install.ps1 -OpenDefaultAppsSettings
```

For a portable copy, clear the downloaded-file mark once from the extracted
folder with `Get-ChildItem -Recurse | Unblock-File`.

`winget upgrade abooodbah.LeanMark` picks up 0.6.0 once the winget community
repository has accepted the new manifest.

## Known gaps

- Windows memory was not measured with `tests/Measure-Performance.ps1` for
  this release; the Linux numbers stand in for it.
- The macOS menu shortcuts and saving the width on macOS were built and smoke
  tested in CI but not used by hand.
- With the outline showing, Full fills the space between the outline and the
  matching margin on the right, not the whole window.
- The settings panel is not modal: Tab moves out of it into the page.
- The macOS preview remains ad-hoc signed and not notarized, so Gatekeeper may
  require an explicit approval in **System Settings > Privacy & Security**.
